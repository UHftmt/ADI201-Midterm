# Presentation Checklist

Tick each box before Thursday's presentation.

**The night before**

- [ ] I can run the merged system from a **clean folder** with one command, on the laptop I will bring.
- [ ] I have a backup (a short recording or screenshots) in case something fails.
- [ ] I have no key, token, or password in the repository, the terminal history on screen, or my notes.

**My 3-minute demo**

- [ ] One complete path through the idea, from the user's side.
- [ ] One rejected input, and I say its outcome word.
- [ ] I say which of the seven Difficulty Bar features each part shows.
- [ ] I name one commit that is mine and show it.
- [ ] I close with my **job link** (workbook 7.3) in one sentence: a real job task my tool maps to, and one thing it needs before real use.
- [ ] I have practiced it with a timer and it fits in 3 minutes.

**My 1-minute challenge**

- [ ] I can explain every component, including ones I did not write: what it does, and what fails if it is removed.
- [ ] I know where the state table, the roles, the stored data, and the sandboxed step live in the code.
- [ ] I can predict what `run.py` prints before I run it.
- [ ] I can add or change one rule and name the cases that change.
- [ ] If I use my agent, I will read what it proposes before I run it.

**ADI501 only**

- [ ] I can defend my continue / revise / stop thresholds: why those numbers, and what I do if the pilot lands just below the revise line.
